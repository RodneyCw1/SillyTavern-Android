# 更新与覆盖安装验收

公开构建保留 SillyTavern 1.19.0 原生功能。Node 回归测试 162 项及 Android 更新策略测试 6 项通过，GitHub 的干净 Windows 构建通过 Android 单元测试、Lint、原证书签名、16 KB 对齐及 APK 内容审计。APK 不含第三方预装插件、角色卡或世界书。

在专门创建的 x86_64 模拟器上，从原版 1.1.4 覆盖升级并重启，合成测试角色卡、世界书、聊天、API 配置、密钥及插件/工坊下载状态的文件 SHA-256 保持一致；原版已安装的三个第三方插件也保留。Android 10 使用 4 KB 内存页，Android 15 使用 16 KB 内存页。测试材料没有使用或上传个人内容。

连续 main 推送产生递增版本及独立公告；重跑较早工作流没有重复公告，也没有改变较新 Latest。更新清单固定仓库、包名和原签名，按数字 versionCode 比较。下载由 Android DownloadManager 持久保存，界面支持取消、后台下载及重新打开后读取进度。

Android 10 的 `getPackageArchiveInfo` 只有在同时请求 `GET_SIGNATURES` 时才会实际收集 APK 证书，单独请求 `GET_SIGNING_CERTIFICATES` 会得到空签名信息。已在真实 Android 10 模拟器复现，并改为同时请求两个标志；仍严格比较当前 `apkContentsSigners` 与原证书。实现依据见 [AOSP Android 10 PackageManager](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-10.0.0_r1/core/java/android/content/pm/PackageManager.java)。

Android 15 测试镜像自带的 WebView 124 曾在旧 APK 和新 APK 的主进程内发生 MemoryInfra 原生崩溃，后台 Node 继续运行。该平台问题未标记为修复。Android 10 的界面及更新操作单独验收；模拟器测试不能代替 ARM64 真机或厂商后台策略测试。Linux 重建流程及源文件已提供，本轮没有重编耗时较长的 Node C++ 运行库。
Android 10 已用真实 DownloadManager 验证下载、取消、断网后的重试，以及应用重启后继续使用原下载记录。大小不符、字节损坏和不同签名的 APK 均被拒绝；错误签名使用实际重新签名的 APK 验证。后台聊天、未完成保存队列及保存失败阻止安装，伪造安装 nonce 被拒绝。拒绝安装来源权限或取消系统安装后，已有数据和已下载更新继续保留；再次安装完成原签名覆盖升级。故障包测试通过模拟器上的独立测试工具准备 DownloadManager 已完成记录，该工具没有包含在公开源码或 APK 中。

取消流式请求时，上游处理器可能移除 HTTP socket 的内部 close 监听，导致响应对象不再发出 close/finish 事件。保存屏障现同时清理已断开的连接，防止取消聊天后永久阻止更新；新增真实 HTTP 连接回归测试，确认正常保存仍阻止安装、保存完成和流式取消均正确释放屏障。

2026-10-17 验证大型 PNG 角色卡导入：在 Android 10 / x86_64 / 2 GB RAM 模拟器安装当前公开 build.6，导入一张 43,520,088 字节、含 318 条世界书及 16 条正则的原卡，60 秒内未返回，服务同时无法响应其他请求。问题来自逐字符解码全部 PNG 文本，以及保存时再次解码旧元数据。修复改为 Buffer 视图读取关键字，仅解码优先使用的一份角色数据，并减少整图复制，保留 CRC 校验、V3 优先规则及其他 PNG 数据块。

使用原证书签名的修复 APK 覆盖安装后，同一导入接口在约 1.8 秒内返回成功，已保存的世界书与正则内容逐项一致；确认导入内嵌世界书、允许角色正则并打开角色后，重启应用仍可读取全部 318 条世界书和 16 条正则。覆盖升级前已有 350 个合成测试数据及扩展文件的 SHA-256 保持一致。169 项 Node 回归测试、Android 单元测试、Lint、APK 资源审计及 16 KB 对齐检查通过；新增超过 40 MB 的合成双元数据卡回归测试，在 256 MiB JavaScript 堆限制下验证读取、编辑和重新加载。原卡和本地测试证据未加入公开源码或 APK。本轮设备验证限于 x86_64 模拟器，未连接 ARM64 真机。

同日验证 Android 内嵌角色界面适配：原卡在 393 CSS 像素屏幕中只有约 271 像素的消息框，模式说明被挤至约 26 像素并裁切。仅在 Android 宿主为酒馆助手消息 iframe 释放头像占用的宽度，窄屏模式选择改用图标和说明的网格布局。原签名修复 APK 覆盖安装后，原卡通过 320、360、393、412 像素竖屏和 786 像素横屏的内容边界检查，玩家与编剧模式均可进入；普通消息保留原布局。

对具有左右抽屉结构的角色页面增加关闭事件兜底并扩大关闭键触控区域，避免原卡关闭委托未初始化或点击冒泡被阻止时无法收起。合成浏览器回归先复现无法关闭，再验证叉号、遮罩、连续开关、双面板状态、iframe 导航和新消息重建；同源限制及其他 iframe 保持不变。原签名修复 APK 使用原卡及合成正文触发实际游戏界面，通过触控验证角色面板连续三轮开关、交互面板关闭、点击遮罩收起，以及主动移除原卡事件委托后的关闭兜底。170 项 Node 回归测试、Android 单元测试、Lint、APK 审计及 16 KB 对齐检查通过；覆盖升级前的 350 个合成数据文件校验保持一致。角色卡及插件只用于本地验收，未修改原卡或打包进公开 APK。

同日验证大型角色卡长聊天：使用用户指定的兼容 API 成功完成 15 次短生成，在本地构造 30 条消息的聊天记录；手机上的原始记录未导出，未将个人聊天发送给服务商。build.8 在 Android 10 / x86_64 / 2 GB RAM 模拟器重现页面进程退出，渲染进程 RSS 峰值约 1,332 MiB。Android 宿主现在仅对含大型 HTML 替换模板的卡片分段显示历史，一次保留两条消息，支持较早、较新和返回最新；原始聊天数组、消息绝对编号及变量保留，普通卡片和浏览器端继续原有行为。切换历史前释放旧的插件 iframe 运行环境，历史选择保存在轻量宿主设置中，避免每次切换重新提交整张大卡。

另复现模板插件对渲染后的界面文本计数：约 8.25 MB 的 HTML 被提交至 Llama 分词器，后台内存继续增长并被系统回收。Android 端现将匹配消息代码块或已允许的显示模板的界面展开文本，映射回原始回复及推理文本计数；延迟回调在旧界面释放后也受保护，不截断其他文本。修复后该请求由约 8.49 MB 降至约 244 字节，持续运行约 143 秒时页面与后台均存活，RSS 分别约 411 MiB 与 201 MiB。原签名修复 APK 验证关键脚本与源码的 SHA-256 一致，再通过四轮历史翻页、保存后重开及继续下一回合；完整消息保留，分词请求保持小于 4 KiB，后台仍存活。覆盖安装前后的 350 个合成文件校验保持一致。176 项 Node 回归测试、Android 单元测试、Lint、APK 审计及 16 KB 对齐检查通过。密钥只用于本地测试，原卡、生成记录和第三方插件均未加入公开源码或 APK。
